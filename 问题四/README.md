# 问题四复现说明

所有主程序均为Python，使用现有Anaconda环境，不需要安装包。问题三源文件只读。代码和结果按两个子问题归档：`子问题一`存放分区配置优化与提交表，`子问题二`存放资源缺口、实际分配和独立核验；共享输入快照和总入口在问题四根目录。`输入快照冻结清单.json`保存冻结文件指纹。

在项目根目录用PowerShell 7执行：

```powershell
& 'E:\tool\anaconda3\python.exe' -X utf8 '问题四/solve_q4.py'
& 'E:\tool\anaconda3\python.exe' -X utf8 '问题四/verify_q4.py'
```

依赖：numpy、scipy、openpyxl、torch、psutil，均使用本机既有版本。求解器为SciPy/HiGHS；GPU要求两张CUDA可用设备。无随机搜索或种子影响。

首次冻结已完成。需要从源目录重建时运行`freeze_q4.py`，该步骤复制输入、使用4进程重建通信；若原第三问快照变化，应作为新实验管理，不能与既有结果混用。当前输入全在本目录，可直接重复求解和验证。

程序分工：

- `q4_core.py`：十进制有理数、实际通信关联、完整分区、峰值、原双目标和遗憾。
- `q4_checks.py`：集合划分MILP、残差修正的有效LP下界、两张GPU并发峰值核对。
- `solve_q4.py`：总入口，顺序运行两个子问题。
- `子问题一/solve_partition.py`：主方案、备选、敏感性及官方Excel模板导出。
- `子问题二/analyze_resources.py`：资源分配见证、峰值证书、库存缺口及合并收益。
- `子问题二/verify_q4.py`：不导入主优化逻辑，独立图遍历、有标签穷举、事件扫描、资源冲突及提交表回读；根目录`verify_q4.py`为便捷入口。
- `q4_paths.py`：集中维护两个子问题的输出路径。
- `write_q4_results.py`：一次性将已核验结果回填第7章；备份在`审查与备份`，不作为日常求解步骤重复运行。

基准资源顺序为`U_A,U_B,U_C,P_A,P_B,P_C,U_R,P_R`。论文使用C1—C4，程序内部基本单元从0编号。正式文件为`子问题一/问题四_结果提交.xlsx`，包含两组3服务区小组/12服务区大组，以及三组2服务区小组/12服务区大组/S006单区组，共5行。其他Q1—Q3页保留原空白模板，不能将本文件误认为全部四问合并提交文件。`子问题一/render_submission.py`从实际工作簿生成表格预览。

库存不作为默认硬约束。所选两个方案均为补配后可执行的最低独立配置；穷举和库存约束MILP均确认当前快照不存在库存内的2组或3组分区。

实际通信重建使用复制后的第三问DEM内核；第四问独立核验针对分区、资源配置和数据保持，不宣称重新证明另一套传播物理模型。

archive_00/01/02存在约10^-12秒的原资源交接误差，暂停严格配置对比；程序不擅自舍入或改时刻。主快照及archive_03/05/06通过严格检查，完成同口径独立比较。当前极小实例全量缓存仅需有限内存，GPU仅用于核对，不以额外填充负载假称加速。
