# 扩展搜索实现独立复核

2026-09-24；same-family/provisional；只读正在运行的 `search_expanded.py`，未修改生产代码或搜索流程。最终数值复核另见 `independent_review/`。

结论：当前新增流程的扩大库下界、固定尺度遗憾和强制候选探索在数学上成立；截至源码审阅未发现破坏可行性或造成非法下界的实际bug。

## 1. 扩大库LP确为有效下界

设扩大评价库为K。对任意完整可行联合调度，令x_k为路线选择指示，C为该调度实际最后返场。它必然满足逐箱精确覆盖、0<=x<=1、C>=0，以及每一机型g的 `Σ duration_k*x_k <= n_g*C`。后者由同型实体无人机不重叠且全部任务位于[0,C]推出，与电池如何调换无关。

代码在 `collect()` 的 `Aeq` 中保留精确覆盖，`Aub`保留上述分型工作量式，删去全部电池、时序、硬截止和整数限制。因此原可行方案映射必在LP中。对固定非负权重系数α，目标为 `α_N Σx+α_E Σenergy*x+α_C C`，删去非负项α_L L；于是 `LP* <= min真实联合加权目标`。候选筛选已包含物理可行性只会限制K的定义；它不会使此LP失去“同K下界”的性质。

代码没有沿用旧K0下界，新下界由冻结扩大评价库重新求得，范围正确。LP失败时回退0同样有效，因为全部四目标及权重非负，但应在报告中明确该项没有求得更强界。该LP不能认证未生成路线的完整问题，也不能直接将其不带额外ε限制的目标解释为某个特定C单目标界。

独立复核脚本将重排路线及箱索引后重求12个LP，另从等式/工作量对偶构造弱对偶证书：对偶y自由，工作量对偶z<=0，保证C的约化成本非负；其余路线变量有0—1上界，所以 `Σy + Σmin(0,reduced_cost_k)`为有效对偶值。会给出保守数值安全量；它比只比两次 `linprog.fun` 更直接说明下界来源。

## 2. 原冻结尺度与新遗憾

保留原 `冻结评价配置.json` 的正尺度仅规定比较坐标，并不把原K0最优值移入扩大库。代码对12个w都用 `coeff=w/scale`，基准下界来自新LP、上界来自扩大档案完整方案，计算 `max_h(score-upper)`和 `max_h(score-lower)`。这是同一扩大评价库的合法遗憾区间；未减平移常数在方案和基准相减时抵消。

原库与扩大库的遗憾基准不同，所以数值不能简单作为同范围精确遗憾的前后提升百分比；若要严格比较，应将旧代表也用这套扩大库界统一重评。权重.55等搜索方向超出最终δ=.3极点域无碍，它们只是生成候选的启发式目标，最终所有方案由同12极点统一评价。

## 3. 强制新候选确实解除warm回退

强制阶段仅从当前未选的新候选中选择，设置对应x列lb=ub=1，warm=None，未设置旧解加权值所导出的C截断。由此原完整选择方案被排除，求解器不能回退原解；找到的物理可行较差解可以到达退火接受逻辑。没有可行解则拒绝，未把松约束违规方案作为探索。

即使被释放的只是部分货箱，当前完整方案中其他路线也进模型，资源/时间均开放；覆盖结构将未释放箱保留在原路线，仍可重新排全部资源时序。所谓“释放”主要限制可变箱组，而不是把其他任务时刻固定。这是有效的较强邻域，应按实际行为描述。

初始 `important` 已从canonical候选取属性，避免携带历史route_id；MILP解码另移除旧route_id。首轮duplicate被核验拦下是失败运行，保留失败日志即可，不能计为正式可行搜索或静默抹除。

## 4. 仍需限定的搜索/工程范围

- 完整单点目录入库，但随机多点仍为2—5个不同服务区、每站1—3箱；没有完整多点枚举，也没有重复访问生成。
- 额外混合候选的注释“all orders”过强：实际是50次随机组并与随机打乱站序，不枚举全部顺序。只是注释/范围问题，不影响当前方案的可行性。
- 动态新路线进入当前邻域并记入discovered，但没有累积回worker的全pool；该步没选中的新路线以后未必再次供搜索。不过最终评价库合并discovered，所以上下界范围仍包括它们。
- 所有完整候选并未一次性展开进MILP；每一步只抽取有限替代列。通过物理核验并不证明这个邻域或扩大库已求至最优。
- `collect()`用glob收集worker文件，重用同目录且降低worker数可能混入旧运行文件。当前6worker结果应保留配置与源哈希，后续独立运行宜使用新目录或清晰运行ID。
- 终端每方案固定资源最小化L能修正本轮已证反例，但若L已为0，当前终端目标不主动优化C。可以再进行固定路线/资源的C阶段以减少明显未压紧空间，不应把“已调用终端”写成全面Pareto认证。
- `digest()`已加入能耗、duration、charge、offset等系数，比旧仅ID哈希更完整；输入/假设清单还应与运行ID一起核对。使用Python JSON的Infinity序列化可本地复现，但不属于严格标准JSON；这是可移植性问题。

核心结论必须保持：扩大有限库的启发式档案，加上该库的可证放松下界与经核验可行上界；不能升级为完整原题最优或全路线Pareto证明。
