# 历史说明：审计修正后的联合求解

主方法为冻结候选库内的直接联合MILP，ALNS保留为单独记录的简化对照。货箱组批、访问路线、机型、具体无人机、电池和开始时刻在同一个模型中决定；真实架次数、能耗、最晚返场和普通物资迟到共同参与优化。程序不再使用代理选路后固定路线排程来代替该模型。

## 运行

在项目根目录，用现有Anaconda Python执行。无需安装依赖，也不依赖问题一目录。

```powershell
& 'E:\tool\anaconda3\python.exe' -X utf8 -u '问题二/solve_q2.py'
& 'E:\tool\anaconda3\python.exe' -X utf8 '问题二/audit_q2_implementation.py'
& 'E:\tool\anaconda3\python.exe' -X utf8 '问题二/q2_gpu_audit.py'
& 'E:\tool\anaconda3\python.exe' -X utf8 '问题二/report_q2.py'
```

第二、三步失败时应先修复，不能把旧报告当成新运行的验证。第四步覆盖生成报表，并重新读取工作簿比对表头、架次、箱号和数值。主求解可能明显超过单次求解器时限参数，实际预处理、求解和退出时间均记录在日志中。不要并发运行两次主程序写入同一结果目录。

当前环境版本见 `计算资源记录.json`。求解使用SciPy内置的HiGHS接口，配置4个独立CPU求解进程、每个1线程。两个GPU用float64从原始箱重、机型参数及经审计的DEM几何批量重算能耗、时间、SOC和充电时间；整数规划由CPU执行。数据在内存中复用，未为展示占用率而分配无用内存。

`sync_manuscript_q2.py`是本轮第5章一次性精确修订脚本；保留所有图片引用及其他章节，原文锚点不匹配时停止写入。它不是每次重跑实验必须执行的命令。正文改动前的第5章另存于备份目录。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `q2_data.py` | 从原始工作簿读取货箱、资源、充电参数；遍历240条DEM航段；逐箱事件路线与物理量 |
| `q2_candidates.py` | 完整单点逐箱枚举、公开范围的工作库、可复现初始调度 |
| `q2_joint.py` | 同一联合MILP中的覆盖、硬时限、双资源时序、四目标、ε和词典序阶段；有效初始解及限时解保留 |
| `q2_run.py` | 单目标、自适应ε、独立ALNS对照、偏好极点MILP/LP、遗憾区间与代表选择 |
| `q2_verify.py` | 不调用候选物理函数，从原始输入重建并检查完整方案 |
| `audit_q2_implementation.py` | 审计反例、错误注入、重复模式、四站、偏好、迟到阈值、跨哈希种子和独立DEM算法回归 |
| `q2_gpu_audit.py` | 双GPU物理公式复算；不相加已有缓存作为验证 |
| `report_q2.py` | 同一主方案的CSV、模板XLSX、资源与目标表、汇总和文件指纹 |

`solve_q2.py`是标准入口，`solve_q2_new.py`与`q2_model.py`只作兼容转接。旧实现和未验收中间结果隔离在 `备份/`，不作为当前结果读取。

## 数据与复现

读取原始 `调度中心与服务区.xlsx`、`运输无人机数据.xlsx`、`物资需求与配送时限.xlsx` 和 `镇龙乡及周边30米DEM.mat`，支持本地 `D题/数据` 和仓库 `数据/` 布局。模板同样按文件名定位；重复匹配会报错，防止误读。A/B/C无人机4/2/2、电池6/4/4和充电时间1800/2400/3000 s均由附件读取。

`初始化/审计基线方案.json`为可迁移的旧可行初始解，按原始输入重新构建后才使用。`审计修正基线.json`中的旧绝对路径仅为备份来历，不是运行依赖。构造初始解先排序箱号再使用随机数，逐次保存seed和mode。MILP按墙钟限时，硬件竞争仍可能改变探索进度，因此不宣称限时整数求解逐比特复现。
